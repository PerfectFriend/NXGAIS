### Как мы работаем в режиме тандема

1. **Ты** (аудитор) после каждого цикла:
   - Обновляешь этот `AUDIT_REPORT.md`.
   - Чётко разделяешь три секции: ✅ Готово / ⚠️ Ошибки / 🚨 Иллюзии.

2. **Кодер (Женя / AI Studio)** после получения замечаний:
   - В `DEVELOPMENT_LOG.md` отвечает по каждому ID: «сделано / не сделано / отложено до … / нужно уточнение».

3. **Журнал аудита** — это и есть данный файл + при желании отдельный `AUDIT_JOURNAL.md` с хронологией.  
   Главное правило: ничего важного не должно жить только в чате. Всё существенное фиксируется в репозитории.

4. **Цвета**:
   - Синий / ✅ — код, который ты лично признал production-ready. Его не переписываем без крайней необходимости.

## 1. ✅ Готово к проду (Production-Ready) — синяя зона

Эти компоненты соответствуют стандартам надёжности, имеют golden vectors / unit-тесты и могут считаться каноническим ядром.

| Компонент | Путь | Вердикт | Примечание |
|-----------|------|---------|------------|
| Константы протокола, ошибки, Tor v3 | `crates/nexxus-core` | ✅ | Golden vector onion совпадает. Chunk math корректен. |
| GF(2^8) + Reed-Solomon (4+2) | `crates/nexxus-crypto` (основной lib) | ✅ | Gauss-Jordan, восстановление из любых 4 из 6. SIMD-ускорение присутствует. |
| ChaCha20-Poly1305 AEAD | `crates/nexxus-crypto` | ✅ | Через проверенный crate, RFC 8439. |
| Merkle tree (Bitcoin-style) | `crates/nexxus-crypto` | ✅ | Дублирование нечётного листа. |
| Binary Wire Framing + CRC32C + DoS-лимит | `crates/nexxus-wire` (WireCodec) | ✅ | `MAX_PAYLOAD_SIZE = 16 MB` уже стоит. Framing чистый. |
| Unit-тесты core + crypto (golden) | `nexxus-vectors/` + `#[cfg(test)]` | ✅ | Базовые векторы проходят. |

**Резолюция по синей зоне**: не трогать без крайней необходимости. Любые изменения здесь требуют отдельного обоснования и регрессионных тестов.

## 2. ⚠️ Ошибки и недочёты (Issues & Recommendations) — красная зона

| ID | Компонент | Критичность | Описание | Рекомендация |
|----|-----------|-------------|----------|--------------|
| **SEC-PQC-01** | `crates/nexxus-crypto/src/pqc_kyber.rs` | Высокая | Полная симуляция. Нет реальной ML-KEM-768. X25519 = SHA-256 вместо scalar mult. Ключи = XOR-поток из seed. | Либо интегрировать настоящий `ml-kem` / `pqcrypto`, либо **немедленно** пометить весь модуль `[SIM]` в коде, UI и документации. Убрать любые утверждения «FIPS 203» без оговорок. |
| **SEC-ZK-01** | `crates/nexxus-crypto/src/zk_snark_por.rs` | Высокая | Нет Plonk/Halo2/pairing. Всё построено на SHA-256 + XOR. «Pairing check» = сравнение двух хэшей. | Аналогично: реальный SNARK **или** жёсткая маркировка `[SIM]` + запрет на «384-byte succinct proof» в маркетинговых текстах. |
| **NET-QUIC-01** | `crates/nexxus-wire/src/quic_transport.rs` | Средняя | Это не QUIC. Кастомный UDP-фрейминг с magic `NQUC`. Нет TLS, нет настоящего 0-RTT, нет congestion control. | Переименовать в честное имя (`CustomUdpFraming` / `NexxusUdp`) **или** подключить настоящий QUIC (`quinn` / `s2n-quic`). |
| **NET-XDP-01** | `crates/nexxus-wire/src/ebpf_xdp.rs` | Средняя | Только генератор C-исходника + симулятор. Нет загрузки в ядро, нет реальной телеметрии. | Либо `libbpf-rs` / `aya`, либо явный `[SIM]`. |
| **ARCH-DOC-01** | README + `install.sh` / `install.ps1` | Высокая (док) | Документация и инсталляторы всё ещё описывают Node.js-путь, хотя core уже на Rust. | Синхронизировать install-скрипты и README под `cargo build --release -p nexxusd`. |
| **TEST-INT-01** | Весь сетевой стек | Средняя | Нет integration-тестов с двумя живыми процессами/сокетами. | Добавить `tokio::test` сценарии StoreChunk / FetchChunk / PoR между двумя узлами. |
| **STORAGE-01** | `crates/nexxus-storage` (state_channel, io_ring и др.) | Требует отдельного цикла | По паттерну предыдущих модулей высока вероятность симуляций. | Аудит №2 — глубокая проверка storage + DePIN channels. |

## 3. 🚨 Иллюзии / Симуляции / Обман (Закон 1, 7, 10)

Следующие модули **на момент аудита №1** являются симуляциями и обязаны нести красную маркировку:

1. **PQC Hybrid (ML-KEM-768 + X25519)** — 100 % placeholder.
2. **ZK-SNARK PoR** — 100 % placeholder.
3. **QUIC Multi-Stream Transport** — декоративный framing, не QUIC.
4. **eBPF / XDP Filter** — генератор исходника, не работающий фильтр ядра.

**Требование**: до следующего аудита все эти места должны быть либо:
- заменены на реальные реализации с golden vectors,  
- либо явно помечены `[SIM]` в исходниках, UI, README и DEVELOPMENT_LOG.

Любое продолжение презентации этих модулей как «реализованных столпов эволюции» без маркировки считается нарушением Манифеста.
